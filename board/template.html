贯穿各层的规矩

  • 金额只用整数分,浮点进不了账
  • 流水只追加;改账走调整,必须写原因和经手人
  • 单据链:回执 HZ → 日账单 RZ → 结算单 DZ,每笔钱都能追到单据
  • 拿不准就标红,改好才许确认
  • AI 只碰"话"(拆单、话术),数字归确定性代码,发给客户的消息由人点
  • 每次打开总览都跑一遍六项交叉验证
  • 内核不碰平台:换运行时(国内云、单机)内核零改动

能不能用 dsh 这套自演化逻辑

对照 Jarvis 母体蓝图与 dsh 内网协同方案

逻辑能用,今天已经用上了一半;工具不用换;自转先别开。

dsh 在 Jarvis 那边被选中,是因为数据只能放内网。汇金源没有这个约束,而 dsh 还是预览版(11 周 38 个预发布、没有终端界面、审批只有"允许一次")。这里继续用 Claude Code 执行,只借它的做法。

最该借的是那份蓝图对自己的批判:自转不等于前进。它跑了 13 张卡,处理的真实问题是 0;汇金源是同一个症状:19 篇设计、64 项测试,店里真实使用 0 天。

Jarvis / dsh 的做法在汇金源怎么落状态
唯一账本:git 里一卡一条board/cards.json,本页只是它的视图今天建
完成只有一个定义:gatenode tools/board.js check:账本自洽、腿都在、全量测试绿、无 NUL 字节今天建
验收腿测试挂到卡上;店里试用也是腿(L3)今天挂上
门槛只紧不松测试数只增不减(board/ratchet.json);C4 今天加严,能抓住"期初写错"今天做
LESSONS 晋升棘轮LESSONS.md 7 条真实踩过的坑,每条对应一条腿今天建
人只在三道门禁出现方向:您定卡;数据:AI 不碰金额;对外:发给客户的消息由人点产品里早有
被测不能自证:异模复核让另一个模型专门写骗过对账腿的偷懒实现,先拿对账类腿练还没做
验证分层 E0–E5L0 内核到 L4 对方确认今天写明
定时 loop 自转、5 人协作层现在不开:没有真实输入,一个人用不搬

汇金源适合的自演化形态

  • 输入:妹妹每晚在标红处改过的拆单、退回的账单、她的原话
  • 变成腿:每条改错转成一条拆单测试语料,每次投诉转成一条对账测试
  • 执行:改词库或代码,gate 全绿才提交
  • 门禁:您早上批合并;金额规则只紧不松

产品自己也在演化:价格记忆已经在学,语料飞轮和催款规则会跟上。学到的东西一律过确认闸,和研发 gate 是同一个思路。

什么时候开 loop

  • 店里连续用满一周(V01)
  • 攒到至少 20 条真实改错
  • 先手动跑三晚"改错转腿",确认值得再定时

证伪:开 loop 两周后,她标红改错的次数没有下降,就停掉,回到人工按反馈修。
