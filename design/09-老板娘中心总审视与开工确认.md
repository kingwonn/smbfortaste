# 09-老板娘中心总审视与开工确认

**这篇是什么:** 方案持有者对产品本质的最终定调——**"这个系统本质上是要完成老板娘的工作,为老板娘减负:客户的需求收集好→原材料采购→分发配送→核对送的对不对→没问题收钱、有问题处理→把员工安排好→最后收到钱。要让她工作舒服,减少工作强度和出错概率。"** 本篇以此为唯一标尺做最后一轮终审:她的七个环节逐一对照系统承接情况、收录终审报告全文、裁定范围修订,并给出开工确认。**本篇之后,设计冻结,进入 M0。**

---

## 一、产品本质(一段话钉死)

这不是"给门店的管理软件",是**老板娘的数字分身**:她原来用脑子记、用手抄、用嗓子对的每一件事,系统要么替她干掉,要么替她记着、到点递到她眼前。衡量一切功能的唯一标尺:**这个功能让老板娘今天少干了几分钟、少错了几次?** 答不上来的功能不做。

## 二、她的七个环节:对接主体、信息、系统承接

| # | 环节 | 对接谁 | 关键信息 | 系统承接(模块) | 终审后剩余人工 |
|---|---|---|---|---|---|
| 1 | 收集客户需求 | 客户(核心) | 谁、要什么、多少、何时送 | 贴单拆分/手点开单/周期单/接龙(模块5)+**断订雷达(本篇新增)** | 扫一眼确认卡、断订户问一句 |
| 2 | 原材料采购 | 供应商摊主 | 缺什么、买多少、什么价 | 采购汇总单三视图(模块6,M2);供应商端(模块15,M3) | M1 老板照单采购、勾选记价 |
| 3 | 分发配送 | 配送员 | 谁的货、哪条线、几件 | 装车配送单+路线任务(模块7)+**备货装车核对单(本篇新增)** | 按单勾着装,不再凭记性 |
| 4 | 核对(送的对不对) | 客户+配送员 | 签收了吗、有无差异、给不给折扣 | 签收回执+差异闸门(模块8)、**今日对账工作台**(模块10,P0) | 每晚20户30分钟过一遍 |
| 5 | 没问题收钱/有问题处理 | 客户 | 谁该结了、谁有异议 | 结算单+收款跟踪+军师催款(模块9/10)、**问题登记(本篇新增)** | 点头催不催、处理异议 |
| 6 | 安排员工 | 配送员 | 谁跑哪条线、干得怎么样 | 线路指派/进度/表现周报(模块7 增补,M2) | 排班决定、奖惩兑现 |
| 7 | 钱到账 | 客户+配送员 | 今天该收多少、实收多少 | 记一笔收款(模块9)+**现金日清核对表(本篇新增,M2)** | 数现金、认差额 |

## 三、终审报告(全文收录)

以下为独立终审人以"老板娘的一天"走查全部设计后的报告原文,分级:必须补/应该补/可以缓。

### 开场:现设计下她的一天(M1口径)

| 时段 | 她要干的事 | 系统接了 | 还压在她身上 |
|---|---|---|---|
| 清晨5-7点 | 翻微信收凌晨单→贴单/手点;逐单回复述确认;分拣、贴标、装车、出车点数 | 拆单翻译、红格防错 | 30条确认文本逐条复制回微信;**分拣装车核货全程无界面无单可依**;常订客户没下单,没人提醒她 |
| 上午 | 店里接电话单手点开单;客户微信来投诉"醋不对" | 手点九宫格≤30秒 | **投诉只能记在脑子里等到晚上**;"有改动"单挂起,要等下午纸质回执才能改 |
| 下午 | 配送员回店交四样(单、钱、桶、对账联);处理待改账;逐笔记转账 | 待改账队列、记一笔≤10秒 | **现结应收对实收无核对表**;空桶登记仍靠纸 |
| 晚上9点后 | 截单→贴单批量确认→清待改账→今日对账工作台20户→今日待转发→日结对钱→看该催的账、未回应清单 | 每一段各自都有页面且达标 | **七八个角标队列靠她自己记得巡逻**;现金盘点无;连续约60分钟不断档 |

结论先行:单看每一段,设计都算精良;串成一天看,**信息没有汇到她一处,一天的头(需求进池前)和腰(晨间备货、白天投诉)有三个系统性空洞**。

### 必须补

**1.【必须补】没有"今日要办"统一收件箱——最大的负担残留。** 现设计给她的待办散落至少八处:待确认订单、待改账队列、今日待转发、该催的账、未回应清单、异议队列、绑定审批、收款跟踪。首页四大按钮至今是老板视角,老板娘的活全靠角标寄生。方案本质是"把所有信息从她的视角串起来",现设计却要求她记得八个入口——记性负担只是换了个形态。任何一个角标漏看,就是一单错账或一笔漏催。

**2.【必须补】需求收集只防"忘处理",不防"没进池"。** "漏单率=0"机制只管进了池的单。周二必订的老王家今天没发语音,系统毫无反应:周期单只覆盖固定单客户,"断订提醒"被放在 M3 的 L2 分析。而"客户晚上打电话怪你没送"恰是她最怕的事,纸质时代靠清晨逐个聊天窗口翻一遍兜底,系统反而没接这层。基于历史下单频次做截单前提示+一键问候话术,是规则活,不需要等 M3。

**3.【必须补】订单变成车上的货,这一环是空白。** docs/04 有完整纸质流程(分筐贴标、照单点数、出车交接),系统侧"按客户=送货清单"没有任何承接界面,模块7只做配送员路线页,打印在M2。即 M1 清晨,老板娘要么抄手机屏幕分拣,要么退回手抄单。装错货、漏装是全天最大错误源,拍照回执闸门只能事后发现,事前核货无人无屏。

**4.【必须补】问题处理白天没有入口,退换货没有闭环。** 中午客户微信说"今天的醋不对",系统最早的落点是晚上日对账工作台的行级【退货】——从中午到晚上,这件事只存在于她的脑子和微信里,正是要消灭的"脑子记着,一岔就忘"。且退货/换货落成调整分录后不生成次日补送任务,与明日配送单断链。

**5.【必须补】收钱的最后一米:现金日清核对没有系统承接。** 回车交接逐笔核对现结、日结对钱是防糊涂账的核心制度,系统侧只有"记一笔收款";"日结页"被多处引用却从未被规格化;没有"今日现结应收 vs 实收"核对表,现金盘点、差额归属无落点。

### 应该补

**6.【应该补】晚间录入防错三件缺二**:重复单无去重(同客户同日双单不拦)、售价偏离常价无警示(采购侧有±10%提示,销售侧无)、相近客户名错归无运行时确认(老王面馆/老王饺子馆)。她晚上最累时干这些活,防呆恰恰该在这。

**7.【应该补】"把员工安排好"只落了三成**:配送员与线路的指派关系没设计(谁跑哪条线、请假换线);老板娘端当日配送进度监控未规格化;配送员表现(签收齐全率/回执质量/现结上交及时性)数据全在库里,差一张周报。

**8.【应该补】晚间总强度不降反升,且无流水线编排**:晚9点后五件事约60分钟连续操作,顺序全靠她自己拼,应串成"下一步"向导;30单确认文本逐条复制回微信击穿"切换≤3次"预算,应并入待转发队列统一处理。

### 可以缓

**9.** 采购侧应付账在M3,纸质制度兜着,可接受。**10.** 空桶周转物无承接,M2补勾选项。**11.** 期初理老账应给批量粘贴录入,一次性痛,忍得住。

### 终审人:M1 只许再加三样

1. **"今晚要办"统一工作台**——一页收拢全部角标队列,按"现在该干哪件"排序,干完划一件;
2. **断订雷达**——按历史频次,截单前列出"平时今天必订、现在没动静"的客户+一键问候;
3. **备货装车核对单**——分拣逐行勾、装车按线点数、出车确认件数,掐掉全天最大错误源。

现金日清核对表排第四,纸质三道闸尚能顶住;上面三样在现设计里是彻底的零。

## 四、终审裁定:范围修订(已落 design/06)

| 采纳项 | 定级 | 说明 |
|---|---|---|
| "今晚要办"统一工作台(手机+电脑同一页) | **P0 / M1** | 八个队列收拢一页、按序排列、干完划掉;老板娘登录后的默认首页 |
| 断订雷达 | **P0 / M1** | 历史下单频次规则版:截单前1小时提示+一键问候话术;M3 的 L2 流失预警是它的加强版 |
| 备货装车核对单 | **P0 / M1** | "按客户送货清单"落成界面:分拣勾行、按线点数、出车确认;配送员端联动 |
| 问题登记(轻量) | **P0 / M1** | 白天随手一条【记个问题】挂到客户+当日单,晚上日对账该户置顶;成本极低,消灭"脑子记着" |
| 退货→次日补送任务联动 | P1 / M2 | 调整分录可勾"明日补送",自动进明日装车单 |
| 现金日清核对表 | P1 / M2 | "今日现结应收 vs 实收"逐笔核对+差额归属;M1 纸质三道闸过渡 |
| 录入防呆三件(去重/价格偏离/相近名确认) | P1 / M2 | 晚间批处理场景全部启用 |
| 员工安排三件(线路指派换线/进度监控/表现周报) | P1~P2 / M2~M3 | 周报只读不排名,奖惩是老板的事 |
| 晚间"下一步"向导 | P1 / M2 | 把晚间五件事串成一条流水线,做完一步自动带到下一步 |
| 确认文本并入待转发队列 | **P0 / M1** | 复述确认不再逐单切微信,与卡片转发同一队列一次处理 |

**M1 验收门禁新增三条**(已写入 design/06):⑯"今晚要办"一页收拢全部待办,晚间五件事无需记忆第二个入口;⑰断订雷达对历史周频客户当日断订提示率100%(造数验证);⑱按核对单分拣装车,本店实测一周装错/漏装=0。

## 五、修订后她的一天(前后对照,数字均为示例)

| 时段 | 纸质时代 | 系统后(M1+M2) |
|---|---|---|
| 清晨 | 翻聊天记录逐个记单40分钟;凭记性分拣装车 | 贴单批量确认10分钟;**照核对单勾着装**;断订雷达代替翻聊天窗 |
| 上午 | 投诉记脑子里 | 【记个问题】3秒落袋,晚上自动置顶 |
| 下午 | 对现结靠心算、转账逐笔翻 | 待改账队列+记款≤10秒;(M2)现金核对表逐笔勾 |
| 晚上 | 记账对账1小时+,月底另欠3天 | **"今晚要办"一页串完约40分钟**;月底结算单零手工、争议≈0 |
| 月底 | 翻单3天、上门逐户对 | 结算单自动生成,收款有军师盯着 |

强度上:晚间从"散落的1小时+月底3天"变为"一页式的40分钟+月底约0";错误概率上:转写标红、装车核对、去重与价格防呆、日账双方当天确认、夜间自动对账校验,五道闸从头压到尾。**她的工作从"记住所有事"变成"处理递到眼前的事"——这就是减负的定义。**

## 六、开工确认(可以开始干了)

设计冻结于本篇。动工顺序:

1. **本周(不写代码)**:启动 design/06 六.启动检查单——本店开始记基线数据(对账耗时/回款天数/纠纷次数),攒 M0 测试素材(50段真实订货语音转文字文本),约3位真实客户参与触达实测;
2. **M0(2~3周)**:design/06 三.M0 六项假设打靶(触达实测/贴单POC/取号压测/ASR实测/支付进件调研/基线数据),**任一不过,回 design/05 启 B 计划,不带病进 M1**;
3. **M1 第1~2周**:账务内核四件事(取号/核销分配/物化余额/结算幂等)先定稿先压测,再动界面;
4. **M1 全程**:以本篇第二节七环节表和 design/06 门禁(现共18条)为验收唯一依据,本店真实跑满一个自然月出厂。
