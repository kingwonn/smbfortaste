# 20-研发看板与自演化

**这篇解决什么问题:** 方案持有者要三样东西:需求和开发看板、系统架构与演进空间、以及"能不能用 dsh 这套自演化逻辑"。dsh 指 DeepSeek Harness(deepseek-ai/deepseek-harness)。11/13 按其源码(0.2.2-rc.3)核实了它自己的两条自演化路径,并对照 Jarvis 母体蓝图(kingwonn/ycfs)。本篇结论:**研发棘轮全盘借,已落地;运行时自扩展只借给配置,不碰账;工具本身先不换;店里的 AI 将来接 DeepSeek 模型;定时自转先不开。**看板页面由 `node tools/board.js html` 从账本生成。

## 一、看板:账本、gate、视图三件套

| 部件 | 文件 | 作用 |
|---|---|---|
| 账本 | `board/cards.json` | 唯一真相。54 张卡,每张有泳道、状态、来源(用户原话或设计篇目)、验收腿 |
| gate | `node tools/board.js check` | 完成的唯一定义:账本自洽、完成项都有腿、测试腿在代码里找得到、全量测试绿、测试数不低于棘轮下限、源码无 NUL 字节 |
| 棘轮 | `board/ratchet.json`、`LESSONS.md` | 测试数只增不减(`--bump` 抬高下限);真实踩过的坑记进 LESSONS,每条对应一条腿 |
| 视图 | `board/board.html` | 由账本加 gate 结果生成的页面,不手改 |

腿分五类:`test`(gate 自动跑)、`browser`(真浏览器人工走查)、`shop`(店里真实使用)、`doc`(交付物是文档)、`todo`(还没写的腿,有它的卡不许标完成)。

## 二、系统架构(现状)

- **入口**:客户照旧发微信;老板娘复制粘贴进工作台(收单守护的提取层已做,屏幕捕获层未做);体验版同界面加真内核;小程序只有骨架。
- **服务层**(`app/server`,Hono):单机 `run.js`(sqlite 文件、每日备份、局域网口令)在用;Cloudflare Workers(D1、R2、Cron)写好未部署。
- **内核**(`app/core`,平台无关、零依赖):账务四件事(取号、流水余额、收款分配与账龄、账单快照),业务(回执、收单箱、规则与 AI 拆单),备好引擎(价格记忆、总览、六项验证、汇报、往来账)。
- **存储适配**:MemoryStore(测试、体验版)与 D1Store(本地 sqlite、CF D1),同一契约。
- **验证分层**:L0 内核测试、L1 接口端到端(gate 自动跑);L2 真浏览器走查(人工触发);L3 店里真实使用(0 天);L4 饭店老板回"好"(未开始)。层与层不互相冒充。

## 四、DeepSeek Harness 的自演化逻辑:借什么、不借什么

### 1. 它有两条自演化路径(源码核实)

- **研发棘轮(它自己怎么被开发)**:`docs/postmortem` 只收"隐蔽、系统性、重查代价高"的事故,每篇必须回答"为什么每道防线都没拦住",并链接由此加上的测试、AGENTS.md 规则和 `docs/defensive-patterns`;AGENTS.md 要求"把可机器检查的不变量接进顶层 gate,并证明每条改动过的验收路径能拒绝一个无效案例";凡是模型或用户看得见的变化,都要更新无密钥回放的录制会话快照,且"修夹具,不修比对器";另有每文件 100% 覆盖率 gate。
- **运行时自扩展(Creator 模式)**:智能体用两个只读工具(`cordis_inspect_list/query`)查看自己的运行时接口,写出插件,在本进程沙箱里试跑(每次运行请求由人批准或拒绝),再由 `plugin_manager.install_bundle` 经另一次批准持久装进配置;配置是按顺序叠加的补丁,重启不丢;项目里的 skills 优先于内置的。

### 2. 在汇金源怎么落

| 它的做法 | 汇金源 | 状态 |
|---|---|---|
| 复盘写清防线为什么没拦住 | `LESSONS.md`,L3 写明 C4 为什么漏掉期初写错 | 已做 |
| 规则接进 gate,并证明能拒绝坏例子 | `tools/board.js check`;C4 加严,测试证明去掉加严就抓不到 | 已做 |
| 录制会话快照,用户可见变化必须更新 | **回放一晚**(`app/server/test/evening-replay.test.js`):两段真实订货原文走完贴单→确认→记账→收款→出日账单→汇报,发给客户的文字逐字比对快照;没有快照直接失败,重录只能显式 `UPDATE_SNAPSHOTS=1` | 11/13 做 |
| 修夹具,不修比对器 | 首次录快照就审出夹具错误(猪脚饭实称),改夹具,记 LESSONS L8 | 11/13 做 |

### 3. 工具与模型

- **执行器不换**:dsh 仍是候选版,要求 Node 24.9 以上,审批只有"允许一次"。看板的账本和 gate 与执行器无关,`node tools/board.js check` 谁跑都一样,将来换成 dsh 不用改任何东西。
- **店里的 AI 接 DeepSeek 模型(R09)**:Anthropic API 不对中国大陆开放,店在大陆;`splitter-ai.js` 本来就与模型无关(注入一个函数),接 DeepSeek API 是一个适配函数的事,拆单结果仍过幻觉拦截和确认闸。需要一个 DeepSeek API Key。

**汇金源适合的自演化形态**:输入是妹妹每晚改过的拆单、退回的账单、她的原话;每条改错转成一条拆单语料测试,每次投诉转成一条对账测试;改词库或代码,gate 全绿才提交;您早上批合并。产品自身的演化(价格记忆在学,语料飞轮和催款规则跟上)一律过确认闸,和研发 gate 同一个思路。

**开 loop 的条件**:店里连续用满一周;攒到至少 20 条真实改错;先手动跑三晚"改错转腿",确认值得再定时。证伪:开 loop 两周后她的标红改错次数没有下降,就停掉。
