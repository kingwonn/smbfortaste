# 13-复杂度、模式与机会三问

**这篇解决什么问题:** 方案持有者的三个直问:①会不会上来做太复杂(Odoo 是否过于复杂,AI 是否让复杂度不再是问题)?②这个模式是不是快驴模式、只是更松散?③除了帮妹妹(**她是这个小生意的真实店主**)减负,县域真空是不是商业机会?本篇三个诚实回答,并据此新增"家用版先行"的实施修订。

## 一、复杂度:AI 降低"造复杂"的成本,不降低"用复杂"的成本

- **Odoo:用是过度,读是刚好。** 它的复杂度(会计科目/多公司/本地化)是给会计师的;我们只取它"应收→核销→账龄"一张表结构的思路,且已在 app/core 用约千行代码+32 个测试实现完毕——**不引入、不依赖、不再碰**。
- **AI 让写代码变快,但复杂度的代价大头在使用端与维护端**:老板娘的学习成本、bug 面积、改动时的心智负担,AI 都替不了。design/09 的标尺(少干几分钟/少错几次)与 design/06 每期"绝不做"清单继续有效,能砍则砍。
- **实施修订:家用版(M1a)先行。** 既然第一个用户是妹妹的店,M1 拆两步:
  - **M1a 家用版(单店,目标 3~4 周,估)**:只做四件事——拍回执挂账(含差异闸门)、记一笔收款(≤10秒)、晚间一键日账单(RZ)、今晚要办清单(简版)。不做多租户计费、行业模板界面、订阅消息、开店引导(手工替她初始化档案即可)。**验收:妹妹真实使用一个月,晚间对账时间和纠纷次数下降。**
  - **M1b 产品版**:M1a 验证后,补开店三步/多租户/断订雷达/装车核对单等,回到 design/06 原 M1 门禁。
  - M0 六项打靶不变,但优先级向"妹妹店里立刻能测的"倾斜(基线数据、真实语料、触达实测都出自她的店)。

## 二、模式:不是松散版快驴,是快驴的反面

| | 美团快驴(平台自营) | 本项目(商户工具) |
|---|---|---|
| 谁是卖家 | 平台自己(集采、中央仓、统一价) | 本地个体户(妹妹们),各做各的生意 |
| 碰不碰货与钱 | 碰:吃差价、担库存与履约 | 不碰:只数字化账与单据 |
| 与本地商户关系 | **替代**他们 | **武装**他们 |
| 资产模式 | 重(仓配、地推、补贴) | 轻(SaaS,月成本几十元) |
| 县域结局 | 2021 扩到三线即撤(实证) | 恰好接住平台做不了的赊销人情账 |

类比:**快驴之于我们 ≈ 京东自营之于 Shopify。** 快驴的县域失败不是我们的坏消息,是市场形态的证明:这门生意的正确单元就是本地个体户,工具化是规模化服务他们的唯一方式。"更松散"若指远期同行联盟/集采撮合——design/03 第六节已封死:不碰交易、不抽佣,那条路会把轻产品拖成重生意。

## 三、机会:真空是真的,真空≠金矿;帮妹妹是确定收益,商业化是零成本期权

1. **巨头退潮(design/12)证明的是"平台模式在县域不行",不证明"工具模式行"。** 工具模式自己的死穴是有赞/微盟教训:小微流失+获客成本吃掉年费。我们的对策(免费方法论获客、软件长在交易关系里)目前仍是**假设**。
2. **天花板已算过(docs/09,均示例)**:1~3 万家 × 300~1000 元/年,1% 渗透约 9~18 万/年、5% 约 50~90 万/年——副业到小团队的"小而美",不是风投故事。用这个口径做投入决策,不许膨胀。
3. **"是不是商业机会"不该由愿望回答,该由 M0 数据回答**:妹妹店的回款天数/对账耗时/纠纷次数前后对比(付费钩子的因果验证)+ 批发市场 30 家地推 365 元成交率≥10%(示例)。两条都成立才谈推广,一条不成立就停在家用版。
4. **但决策结构使它无论如何值得做**:手里有三样别人没有的——真实样板店(妹妹的店)、零获客成本的第一批用户(同一批发市场的同行)、说人话的行业知悉。**帮妹妹是确定收益**(一家店省的时间+减少的坏账可能就值回全部投入,且 docs/templates/Excel 已交付在先);**商业化是成本近乎为零的期权**,数据好就行权,不好就不行权,没有下行风险。今天不需要回答"是不是机会",只需要把家用版做出来、把数据记起来。

**一句话压住本篇**:为一个真实的人(妹妹)做小而对的东西,把"是不是生意"交给她店里的数据——复杂度上家用版先行,模式上做快驴的反面,机会上不赌愿望赌数据。
